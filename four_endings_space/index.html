The Four Endings

Every conversation with a scripted agent ends one of four ways: contained, abandoned, handoff, or escape. Speedrun all four. The verdict is never the game's: a decision walker (parity-checked against the Python) classifies your transcript live. Instrument by iamdgarcia · trace2grammar

    The Four Endings — what is honest here

    Two bot modes, one referee. By default the bot is a table-driven reply engine (no LLM, no randomness). Press model: on and a real 0.5B LLM (Qwen2.5-0.5B-Instruct) downloads to YOUR browser (~350 MB, WebGPU, no API keys, no backend) and writes the bot's words. The flow brain stays deterministic in both modes: it decides when tools fire, when a handoff happens and when the call closes — so the four endings always exist.

    The verdict is the walker's, not the game's. After every turn the parity-verified JavaScript port of trace2grammar's infer_states classifies the accumulated transcript (tau_port.js, 585/585 parity against the Python on the repo fixtures). The walk you see is the walk it computed.

    Escape is an audit check. In the paper, compliance escape is detected post-hoc (the agent said things outside its allowed script), never as a walk state. In table mode the scripted leak prints the walker's real tables. In model mode there is no script to leak: your injection line goes to the model and the audit scans what it ACTUALLY said for leaked internals; if it never leaks, you never get the ending. The raw walker still sees an unfinished conversation; the game labels it an audit check, exactly like the paper.

    Abandoned is yours to make. Leave mid-flow (button, or 45s of silence) and there is no terminal event: the walker rules abandonment on what exists. That is the real failure mode this instrument watches: confident closing, silent abandonment.
